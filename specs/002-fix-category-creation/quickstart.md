# Quickstart Guide: fix-category-creation

본 가이드는 카테고리 추가/수정 에러 수정 기능을 로컬 개발 환경에서 빠르게 기동하고 TDD 검증을 완수하는 절차를 정리한다.

## 1. 개발 환경 구동 및 종료

프로젝트 루트 폴더에서 제공하는 쉘 스크립트를 사용하여 DB 및 서버를 기동한다. (기존 8080 포트를 점유하고 있던 타 프로세스가 사전에 완전 종료되었는지 확인한다.)

```bash
# 데이터베이스 컨테이너 + 백엔드 + 프론트엔드 구동
./start.sh

# 동작 확인 후 종료
# Ctrl+C로 프론트/백엔드 프로세스 중지
docker-compose down
```

---

## 2. 빌드 및 TDD 검증 (TDD & Build Verification)

코드 변경 이후, 헌법 v1.0.0의 원칙(TDD First 및 Build Verification)에 따라 검증 프로세스를 수행한다.

### A. 백엔드 테스트 및 컴파일 검증
백엔드는 단위 테스트가 우선 동작하고 컴파일 에러가 없어야 한다.
특히, 신규 카테고리 검증 테스트 케이스들을 통과해야 한다.

```bash
# 백엔드 컴파일 및 전체 테스트 빌드 수행
./gradlew clean test
```

### B. 프론트엔드 빌드 및 린트 검증
프론트엔드 코드 수정 이후 빌드 및 ESLint 린트 오류가 없는지 검증한다.

```bash
cd frontend

# ESLint 검사 수행
npm run lint

# TS 컴파일 및 Vite 프로덕션 빌드 검증
npm run build
```

## 3. 핵심 기능 수동 검증 순서

개발 서버 구동 후 브라우저(`http://localhost:5173/settings`)에 접속하여 다음 절차대로 기능이 정상 작동하는지 수동 검증한다.

1. **카테고리 이름 필수값 검증**:
   - 카테고리 추가 모달을 열어 이름을 빈 상태 혹은 공백(`"   "`)만 입력하여 "추가" 버튼을 누른다.
   - 브라우저 상에 "카테고리 이름을 입력해 주세요." 경고 문구가 노출되고, 네트워크 탭에 API 호출이 전혀 일어나지 않는지 확인한다.
2. **카테고리 중복 검증**:
   - 이미 존재하는 카테고리 이름(예: `"식비"`)을 입력하고 저장을 시도한다.
   - 모달 하단에 "이미 존재하는 카테고리 이름입니다." 라는 경고창이나 에러 메시지가 표시되는지 확인한다.
3. **지출 외 카테고리의 연말정산 분류 제약 규칙**:
   - 카테고리 등록 모달에서 유형을 `"이체"` 또는 `"수입"`으로 변경한다.
   - 이때 연말정산 분류 select 입력란이 화면에서 사라지는지 점검하고, 저장 후 카테고리 목록에서 해당 카테고리의 연말정산 매핑이 `"매핑 없음"`(DB 상 `NONE`)으로 고정되어 저장되는지 확인한다.
4. **빈 문자열 역직렬화 처리(Robustness) 검증**:
   - API Client(예: Postman/Curl)를 사용해 `yearEndCategory` 값을 `""`(빈 문자열)로 전송하여 카테고리 추가를 요청해 본다.
   - 백엔드가 크래시나 400 Json Parse Exception 없이 `200 OK`를 정상 응답하며, 카테고리를 데이터베이스에 성공적으로 적재하는지 확인한다.
