# Feature Specification: Simplified Cashflow Ledger & Budget Dashboard

**Feature Branch**: `001-cashflow-ledger-dashboard`

**Created**: 2026-06-25

**Status**: Draft

**Input**: User description: "현재 가계부쪽 헷갈리거나 너무 복잡하게 구현되어 있는 것 같은데 이 부분 분석해서 간단하게 재구현 내가 원하는 가계부는 내 현금흐름(신용카드, 체크카드, 현금, 이체, 소득, 투자, 보험 등) 을 알 수 있도록 하고 싶고, 예산을 정해서 해당 예산 만큼만 썼는지 확인하는 대시보드가 있었으면 좋겠아. 카드사별로 엑셀 파일이나, api로 나의 정보를 받아 올 수 있으면 그렇게 하고 싶고, 안된다면 직접 입력하는 방향으로 구현."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 통합 현금흐름 대시보드 (Priority: P1)

사용자는 이번 달의 전체 자금 유출입 상태(현금흐름)를 한눈에 파악할 수 있어야 한다. 신용카드 사용액, 체크카드 사용액, 현금 지출, 계좌 간 이체, 소득, 투자(저축 포함), 보험료 등 항목별로 유입과 유출 현황이 직관적인 차트와 리스트 형태로 대시보드에 제공되어야 한다.

**Why this priority**: 사용자가 가장 원하는 핵심 가치인 "내 현금흐름의 명확한 파악"을 충족하기 위해 가장 높은 우선순위로 개발한다.

**Independent Test**: 대시보드 진입 시 이번 달에 등록된 모든 거래(수동 입력 및 엑셀 업로드)의 지급 수단(신용/체크/현금/이체) 및 카테고리(소득/투자/보험 등)에 따른 요약 카드가 올바르게 표시되고 총합이 검증되는지 확인한다.

**Acceptance Scenarios**:
1. **Given** 이번 달에 소득 300만원, 신용카드 지출 50만원, 현금 지출 10만원, 보험료 지출 15만원, 이체 30만원이 등록된 상태에서, **When** 대시보드를 조회하면, **Then** 총 유입(소득) 300만원, 총 유출(지출+투자+보험) 75만원, 순현금흐름 +225만원이 표시된다.
2. **Given** 결제 수단별 분석 영역에서, **When** 카테고리별/결제수단별 통계를 확인하면, **Then** 신용카드(50만원), 현금(10만원), 보험(15만원)이 각각 구분되어 차트와 수치로 노출된다.

---

### User Story 2 - 카테고리별 예산 대비 지출 모니터링 (Priority: P1)

사용자는 매달 카테고리별로 예산을 설정하고, 대시보드 및 가계부 화면에서 설정한 예산 대비 실제 지출액을 진척도 바(Progress Bar) 및 경고 표시를 통해 직관적으로 비교·확인할 수 있어야 한다.

**Why this priority**: 예산을 수립하고 이를 초과했는지 모니터링하여 합리적인 소비를 돕는 가계부의 본질적인 기능이다.

**Independent Test**: 예산 설정 후 거래가 추가될 때마다 대시보드의 예산 진척도가 실시간으로 계산 및 갱신되는지 검증한다.

**Acceptance Scenarios**:
1. **Given** 식비 카테고리에 예산 50만원이 설정되어 있고 실제 지출이 30만원인 상태에서, **When** 대시보드를 조회하면, **Then** 식비 예산 대비 지출 비율이 60% 진척도로 표시된다.
2. **Given** 예산 50만원에 지출 55만원으로 예산을 초과한 상태에서, **When** 대시보드를 조회하면, **Then** 진척도 바가 빨간색으로 변경되고 예산 초과 경고 메시지가 표시된다.

### User Story 3 - 수동 거래 입력 인터페이스 단순화 (Priority: P2)

사용자는 기존의 복잡했던 가계부 입력 폼에서 탈피하여, 단일 팝업 모달 또는 단순화된 입력 인터페이스를 통해 날짜, 금액(간단한 수식 지원), 메모, 결제수단(카드 선택), 카테고리를 빠르고 직관적으로 직접 입력할 수 있어야 한다.

**Why this priority**: 엑셀 업로드 외에도 수동으로 실시간 거래를 입력해야 하는 경우가 빈번하므로 사용성을 극대화하기 위해 간소화가 필요하다.

**Independent Test**: 수동 입력 창에서 금액 필드에 수식(예: 5000+3000)을 입력하고 결제수단별(카드/현금/이체) 필수 값을 채웠을 때 정상적으로 저장되는지 테스트한다.

**Acceptance Scenarios**:
1. **Given** 수동 거래 입력 창에서, **When** 금액에 `15000 + 4500`을 입력하고 결제 수단을 신용카드로 선택한 뒤 저장하면, **Then** 금액 19,500원인 신용카드 거래가 정상 등록된다.
2. **Given** 거래 타입이 '이체' 또는 '저축/투자'일 때, **When** 자산(From) 및 대상 자산(To)을 선택하여 저장하면, **Then** 이체 거래로 등록되며 자산 잔액이 정상 반영된다.

---

### User Story 4 - 카드사 명세서 엑셀 가져오기 및 카테고리 자동 매핑 (Priority: P2)

사용자는 카드사별 월별 명세서 엑셀 파일(.xlsx)을 업로드하여 대량의 거래 내역을 가계부에 일괄 등록할 수 있어야 한다. 업로드된 거래는 AI/룰 기반으로 카테고리가 자동 매핑되며, 사용자가 최종적으로 내역을 확인하고 확정할 수 있다.

**Why this priority**: 수동 입력의 번거로움을 줄이고 대량의 과거 거래 내역을 신속하게 가계부에 동기화하기 위함이다.

**Independent Test**: 명세서 엑셀 파일을 업로드한 후 거래 요약 정보(가져옴, 중복 스킵, 실패 건수)와 임시 거래 리스트가 정상 조회되는지 확인한다.

**Acceptance Scenarios**:
1. **Given** 하나카드 이용내역 명세서 엑셀 파일을 준비하고, **When** 엑셀 업로드를 수행하면, **Then** 파싱된 거래 내역이 미확정 거래로 가계부에 일괄 등록된다.
2. **Given** 이미 등록된 명세서를 실수로 재업로드하면, **Then** 중복 검사를 통해 이미 등록된 거래는 스킵되고 신규 건만 등록된다.

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 대시보드에서 이번 달의 소득, 지출, 이체, 저축/투자, 보험 등의 현금흐름을 카드 및 차트로 요약하여 보여주어야 한다.
- **FR-002**: 결제수단별(신용카드, 체크카드, 현금, 은행이체)로 현금흐름 지출 비율을 집계하여 노출해야 한다.
- **FR-003**: 사용자는 카테고리별 한 달 예산을 설정할 수 있어야 하며, 설정된 예산 정보는 데이터베이스에 영속화되어야 한다.
- **FR-004**: 대시보드는 카테고리별로 `실제 지출액 / 설정 예산액` 비율을 계산하여 예산 대비 소비 현황을 진척도 바(Progress Bar)로 시각화해야 한다.
- **FR-005**: 수동 입력 폼은 사용자가 입력 방식을 헷갈리지 않도록 기존의 복잡한 레이아웃을 하나의 간소화된 폼(날짜, 금액 수식, 결제수단, 카테고리, 메모)으로 통합하여 단일 모달로 노출해야 한다.
- **FR-006**: 자산 이동(이체/저축/투자) 거래의 경우, 출금 자산(From)과 입금 자산(To)을 필수 선택하도록 검증해야 한다.
- **FR-007**: 명세서 파일 가져오기 기능은 기존의 하나카드(.xlsx) 외에 주요 카드사(하나, 신한, 국민)의 명세서 파싱 기능을 기본으로 탑재하여 지원 카드사 확장을 지원하며, 중복 결제 등록을 완벽히 방지해야 한다.

### Key Entities *(include if feature involves data)*

- **Transaction**: 거래 내역 정보 (날짜, 금액, 메모, 결제수단, 카테고리, 카드 연결, 출금자산, 입금자산, 확정 여부, 외부참조키)
- **Budget**: 예산 정보 (연도, 월, 카테고리, 예산 금액)
- **Asset**: 자산 정보 (자산 구분 - 현금/적금/주식/부채, 자산명, 잔액, 기본 계좌 설정 여부)
- **Card**: 카드 정보 (카드명, 카드 구분 - 신용/체크, 카드사 코드)
- **Category**: 거래 카테고리 (유형 - 수입/지출/이체, 카테고리명)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대시보드 페이지 로딩 시간이 평균 1초 이내로 유지되어야 한다.
- **SC-002**: 수동 거래 입력 시 사용자의 입력 단계(클릭 횟수 및 폼 복잡도)가 기존 대비 50% 이상 감소되어야 한다.
- **SC-003**: 1,000건의 명세서 엑셀 행을 파싱하고 저장하는 과정이 백엔드 내부 기준 5초 이내에 완료되어야 한다.
- **SC-004**: 업로드된 명세서의 중복 거래 필터링 성공률이 100%여야 한다.

## Assumptions

- **카드사 API 연동 한계**: 국내 개인 카드사의 API 실시간 연동(마이데이터 등)은 공인인증 및 스크래핑 모듈 등 인프라 한계로 본 개인 가계부 앱에서는 구현 범위에서 제외하며, **엑셀 파일 명세서 업로드**와 **수동 입력**을 기본 연동 수단으로 가정한다.
- **카테고리 매핑 AI 모델**: 엑셀 업로드 시 카테고리 자동 분류는 기존의 Gemini API 연동 모듈을 그대로 활용하되, 매핑 정확도를 향상하기 위한 분류 프로필 규칙을 보완한다.
- **예산 설정 주기**: 예산은 월 단위(Monthly)로만 설정 및 평가되며, 일별/주별 예산은 고려하지 않는다.
