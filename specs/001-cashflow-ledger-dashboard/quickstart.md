# Quickstart Guide: Simplified Cashflow Ledger & Budget Dashboard

본 가이드는 가계부 단순화 및 현금흐름 대시보드 기능을 로컬 개발 환경에서 빠르게 시작하고 검증하는 방법을 정리한다.

## 1. 개발 서버 기동 및 종료

프로젝트 루트 폴더에서 제공하는 쉘 스크립트를 사용하여 DB 및 서버를 기동한다.

```bash
# 데이터베이스 컨테이너 + 백엔드 + 프론트엔드를 일괄 구동
./start.sh

# 동작이 확인되면 Ctrl+C로 프론트/백엔드 프로세스는 중지시키고,
# 필요시 DB 컨테이너를 완전 정지하려면 다음을 실행한다.
docker-compose down
```

---

## 2. 빌드 및 TDD 검증 (TDD & Build Verification)

코드가 변경되었을 때, 헌법 v1.0.0의 원칙(TDD First 및 Build Verification)에 따라 검증 프로세스를 실행한다.

### A. 백엔드 테스트 및 컴파일 검증
백엔드는 단위 테스트가 우선 동작하고 컴파일 에러가 없어야 한다.

```bash
# 1. 백엔드 컴파일 및 전체 테스트 빌드 수행
cd backend && ./gradlew build

# 2. 신규 카드 파서 단위 테스트만 단독 수행
./gradlew test --tests "org.example.account.statement.*"
```

### B. 프론트엔드 빌드 및 린트 검증
프론트엔드 소스코드 추가/수정 이후 빌드 및 ESLint 린트 오류가 없는지 검증한다.

```bash
cd frontend

# 1. ESLint 검사 수행
npm run lint

# 2. TS 컴파일 및 Vite 프로덕션 빌드 검증
npm run build
```

## 3. 핵심 기능 수동 검증 순서

개발 서버 구동 후 브라우저(`http://localhost:5173`)에 접속하여 다음 절차대로 기능이 정상 작동하는지 수동 검증한다.

1. **대시보드(`/`)**:
   - 상단 카드의 '총 유입', '총 유출', '순현금흐름' 합계가 올바르게 나오는지 확인한다.
   - 예산 대비 지출(Progress Bar)이 표시되고, 지출이 예산의 80% 및 100%를 초과할 때 게이지 색상이 변경되는지 점검한다.
2. **예산 설정(`/budget`)**:
   - 카테고리별 예산을 금액으로 입력 후 저장했을 때, 데이터베이스에 정상 반영되고 대시보드의 목표 분모로 활용되는지 점검한다.
3. **가계부 거래 관리(`/ledger`)**:
   - 수동 거래 입력 모달을 열어 금액에 수식(`12000 + 4500` 등)을 입력하고 결제수단과 카테고리를 설정하여 등록이 되는지 검증한다.
   - 거래 구분을 '이체' 또는 '저축/투자'로 바꿨을 때, 출금 계좌와 입금 계좌를 강제 선택하게 하는 유효성 검증이 백엔드와 프론트엔드 모두에서 동작하는지 확인한다.
4. **명세서 가져오기(`/statements`)**:
   - 하나, 신한, 국민카드 중 하나를 선택하고 명세서 엑셀 파일을 업로드하여 일괄 등록 및 중복 거래 필터링(중복 재업로드 시 skipped 처리)이 100% 동작하는지 파악한다.
